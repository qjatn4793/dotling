# P0 생성·출력 실험 기록

실행일: 2026-09-23. 상태: 출력 기반 수정 완료, 생성 품질 검증 진행 중. P0 통과 전이며 P1에 진입하지 않았다.

## 출력 변경과 검증

- 기존 `/api/convert`, `/api/generate`의 중복 pixelate를 `src/lib/image/pixelate.ts`로 통합했다.
- 결과는 선택 해상도의 RGBA PNG다. 32 선택 시 실제 32×32이며 8배 확대 저장하지 않는다.
- `cover`를 `contain`으로 바꾸어 비정사각형 입력의 좌우 잘림을 방지했다.
- 배경 제거 결과를 회색 배경에 합성하지 않는다. 알파 128을 기준으로 투명/불투명을 정리한다.
- 색상 수는 불투명 RGB 기준이며 투명 픽셀은 팔레트 추출에서 제외한다. 디더링은 사용하지 않는다.
- 추출한 팔레트를 다음 프레임에 재사용할 수 있도록 colors와 sharedPalette를 제공한다.
- 자연 이미지/기존 픽셀아트 커널 선택, 옵션 검증, 여백, 빈 프레임·경계 접촉 검사 구현.
- 경계 접촉은 잘림 의심 신호이며 의미론적인 무기 잘림 검출은 아니다. 원본에서 이미 잘린 신체를 복원하지 않는다.
- 브라우저에서 투명 체크무늬, 실제 출력 크기, 경계 경고를 표시한다. 다운로드 이름은 생성 당시 크기를 유지한다.
- 요청 실패 시 로딩 해제 및 오류 표시, 미리보기 Blob URL 정리 적용.

변경 전 소스와 합성 입력·출력은 git 제외 경로 `data/baseline/`에 저장했다. 이전 결과는 256×256 RGB, 변경 후 결과는 32×32 RGBA다. 실제 HTTP 업로드로 변경 후 결과의 원본 크기·알파를 확인했다. 프롬프트 타입·해상도·팔레트·잘못된 업로드는 400을 반환했다.

## 로컬 생성 환경

- Node 24.11.1, Next.js 16.2.6.
- ComfyUI 0.21.0, Python 3.12.10, PyTorch 2.11.0, MPS, 시스템 메모리 16 GiB.
- 점검 당시 사용 가능 메모리 약 2.7 GiB. 이 값은 피크 메모리 실측이 아니다.
- 체크포인트: SDXL 1.0, SD1.5.
- LoRA: PixelArtRedmond-Lite64, pixel-art-xl.
- ControlNet/CLIP Vision 모델 폴더에는 모델이 없었고, 사용자 커스텀 노드는 websocket_image_save만 있었다.
- 참조 이미지+자세 제어 방식의 비교와 5캐릭터×3동작 평가는 아직 수행하지 않았다.

### 발견한 기존 구성 오류

`PixelArtRedmond-Lite64.safetensors` 메타데이터의 `ss_base_model_version`은 `sdxl_base_v1-0`이다. 기존 SD1.5 대체 경로에 연결하면 LoRA 키 미적용·텐서 크기 불일치가 발생했다. 실행이 이미지 파일을 반환하더라도 올바른 모델 구성 성공으로 볼 수 없다.

기존 조합으로 만든 idle/run 결과와 workflow는 `data/experiments/2026-09-23T05-23-56.569Z/`에 남겼다. 이 결과는 품질 평가에서 제외한다. 해당 실행의 attack은 클라이언트 실험 중단 이후 ComfyUI에서 완료되었으며 채택하지 않았다.

서비스의 잘못된 SD1.5 대체 경로를 제거하고 SDXL 1.0 + PixelArtRedmond-Lite64 조합으로 변경했다. 체크포인트·LoRA를 모두 확인한 뒤 제출한다. 모델 파일명만 같은 다른 가중치의 호환성까지 자동 검증하는 기능은 아직 없다.

## 재현 명령

ComfyUI가 실행 중인 상태에서:

```sh
node scripts/generation-baseline.mjs
```

SDXL 1.0 + PixelArtRedmond-Lite64, seed 42, Euler 20 steps, CFG 7, 512×512에서 텍스트로 idle/run/attack 시트를 요청한다. 이는 저해상도 기초 실험으로 서비스의 1024×1024/28 steps 프리셋과 다르다. 결과 간 시간·품질을 동일 조건인 것처럼 비교하지 않는다.

입력은 파란 튜닉·은색 투구·갈색 부츠·짧은 검을 가진 측면 기사다. idle은 2×2의 4프레임, run/attack은 4×2의 8프레임을 요청한다. 시트 규칙이 지켜지는지는 사람이 검수해야 한다. 생성 스크립트는 자동 분리하거나 품질 성공으로 판정하지 않는다.

워크플로우, promptId, 원본 PNG, 작업 소요 시간, 시스템 정보는 `data/experiments/<timestamp>/`에 저장된다. 소요 시간에는 대기·모델 로딩·폴링이 포함된다. 실패 후에는 기록된 promptId의 상태를 확인하고 재실행한다.

## SDXL 시트 방식 1차 검수

실행 폴더: `data/experiments/2026-09-23T05-25-08.877Z/`.

| 동작 | 요청 | 관찰 | 판정 |
|---|---|---|---|
| idle | 2×2, 오른쪽 측면 4프레임 | 실제 3×2의 6개 자세. 정면·측면·후면 혼재, 투구 및 몸 형태 변화 | 불합격 |
| run | 4×2, 달리기 8프레임 | 실제 3×2의 6개 서 있는 자세. idle과 매우 유사하며 달리기 동작이 표현되지 않음 | 불합격 |
| attack | 4×2, 검 공격 8프레임 | 실제 3×2의 6개 서 있는 자세. 준비·타격·회복이 표현되지 않고 방향이 혼재 | 불합격 |

idle 작업은 대기·모델 로딩 포함 약 171초, run 작업은 약 92초, attack 작업은 약 64초였다. 이번 프리셋에서는 고정 시드와 프롬프트만으로 요청한 시트 구조와 방향을 보장하지 못했다. 다른 해상도·프롬프트·생성 방식 전체에 대한 불가능 판정은 아니다. 이 이미지를 강제로 4칸으로 나누어 애니메이션으로 제공하지 않는다.

## 남은 작업

1. 완료한 1개 캐릭터의 시트 실험은 3동작 모두 불합격이다. 이 조건으로 전체 5캐릭터 평가를 확대하지 않고 생성 방식을 먼저 수정한다.
2. 기준 이미지 조건과 자세 템플릿을 위한 모델·노드 구성을 선정한다.
3. 시트 생성 방식과 비교한 뒤 5개 캐릭터의 15개 클립을 평가한다.
4. 최대 2회 재생성 후 최소 4개 캐릭터에서 3동작 모두 채택 가능한지 확인한다.
5. 피크 메모리·실제 시간·초기/재생성 후 채택률을 측정하고 P0 통과 여부를 결정한다.

## 검증 결과

- `npm test`: 이미지 회귀 테스트 5개 통과.
- `npm run lint`: 오류 없음, 기존 `<img>` 사용 경고 2개.
- `npm run build`: 성공.
- 실제 HTTP 변환 및 입력 오류 응답 검증: 통과.
- 배경 제거 신경망의 실제 추론 및 브라우저 상호작용 검수는 미실시. IAB 브라우저 연결을 사용할 수 없었다. 투명도 회귀 테스트는 합성 RGBA 입력으로 수행했다.
