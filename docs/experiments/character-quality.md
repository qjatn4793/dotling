# 측면 기준 캐릭터 품질 개선 실험

작성일: 2026-09-23. P0의 단일 기준 이미지 품질 실험이다. 애니메이션 품질 통과와 구분한다.

## 고정 조건

- 파란 튜닉, 은색 투구, 갈색 부츠, 아래로 든 짧은 검을 가진 오른쪽 측면 기사 1명.
- SDXL 1.0, seed 42, Euler/normal, 20 steps, CFG 7. 기본 LoRA는 PixelArtRedmond-Lite64이며, 마지막 비교에서만 pixel-art-xl로 교체한다.
- 얼굴 방향·전신·인원수를 프롬프트 앞에 배치하고 시트·격자는 negative에 명시했다.
- 설치된 ComfyUI의 CLIPTokenizer로 확인한 positive 47토큰, negative 27토큰(특수 토큰 포함). 모델이 지시를 따르는지와 토큰 길이 검사는 별개다.
- 기존 시트 실험과 달리 한 장에 한 캐릭터만 요청한다.
- 각 결과를 공통 프로덕션 pixelate로 64×64/16색 변환한다. 비교용 64 이미지에는 배경 제거를 하지 않아 생성과 후처리 영향을 구분한다.

## 비교 순서

| ID | 해상도 | LoRA 강도 | 이전 조건에서 바뀐 변수 |
|---|---|---|---|
| single-512-lora085 | 512×512 | 0.85 | 단일 캐릭터 기준 실험 |
| single-512-lora045 | 512×512 | 0.45 | LoRA 강도만 변경 |
| single-1024-lora045 | 1024×1024 | 0.45 | 해상도만 변경 |
| profile-1024-lora045 | 1024×1024 | 0.45 | 측면 방향을 강조하는 프롬프트만 변경 |
| profile-1024-pixelxl045 | 1024×1024 | 0.45 | LoRA 파일만 pixel-art-xl로 변경 |
| direction-probe-1024 | 1024×1024 | 0.45 | 짧은 설명과 오른쪽 보행 지시로 방향 제어를 진단 |

동일 시드는 기록·재현을 위한 조건이며, 해상도가 다른 두 출력이 동일한 구도를 갖는다는 뜻은 아니다. 한 캐릭터·한 시드 실험이므로 일반적인 성공률을 추정하지 않는다.

## 채택 기준

1. 오른쪽 측면 전신 1명이며 머리·발·검이 잘리지 않는다.
2. 실루엣에서 머리·몸통·팔·다리·검을 구분할 수 있다.
3. 요구한 의상·장비 특징을 유지한다.
4. 64×64로 줄여도 방향과 장비가 읽힌다.
5. 배경 제거가 캐릭터·검을 훼손하지 않는다.
6. 투명 기준 이미지가 16색+투명, 64×64, 피벗 (32,56) 규격을 만족한다.

기준 미달이면 단순히 비교군 중 가장 낫다는 이유로 채택하지 않는다. 후보와 확정된 기준 이미지를 구분하고, 외형 확정 이후에만 동작 생성으로 넘어간다.

## 실행 및 산출물

```sh
npm test
node scripts/character-quality.mjs data/experiments/character-quality-v1
# 시각 검수한 후보만 후처리한다.
node scripts/prepare-reference.mjs <candidate.png> <output-directory>
```

같은 출력 디렉터리로 재실행하면 기록된 promptId의 결과를 재사용한다. 제출 응답 저장 전 중단된 작업은 중복 제출하지 않고 수동 확인을 요구한다. 설정 변경 시 새 디렉터리를 사용한다.

- `<id>.workflow.json`: 실제 제출 워크플로우.
- `<id>.job.json`: 제출 상태·ID·시간.
- `<id>.png`와 `<id>.64.png`: 생성 원본과 원본 해상도 픽셀 결과.
- `results.json`, `system.json`: 설정·실행 시간·환경.
- `comparison.png`: 위쪽 원본, 아래쪽 64px 확대 비교. 열 순서는 표와 동일.
- 후처리 폴더: cutout.png, reference.png, reference.json, preview.png.

`normalizeReference`는 검수된 기준 이미지에만 사용한다. 후속 애니메이션의 프레임마다 독립 적용하면 크기·위치가 흔들릴 수 있으므로 동작 처리에 재사용하지 않는다. 후처리 파일은 기본적으로 `candidate_requires_review` 상태다.

## 진행 중 관찰

- 512/0.85: 1명으로 분리되었지만 정면에 가깝고 신체·장비가 큰 색 블록으로 뭉개짐. 기준 이미지 채택 불가.
- 512/0.45: 의상과 검의 구분은 개선됨. 그러나 정면 구도이며 요구하지 않은 방패와 추가 검처럼 보이는 선이 생성됨. 기준 이미지 채택 불가.
- 강도 변경만으로 측면 방향 제어가 해결되었다고 볼 수 없음.
- 첫 결과로 배경 제거 실추론과 투명 기준점 정렬을 검증했다. `mask-check` 결과는 후처리 검사 전용이며 채택된 기준 캐릭터가 아니다.

- 1024/0.45: 투구·흉갑·검의 형태가 명확해졌으나 정면에 가까운 구도와 지면 그림자가 남음. 방향 기준 미달로 채택 보류. 해상도 개선과 방향 제어를 별개로 판단한다.

- 고해상도 결과의 배경 제거 후에도 발 아래 지면 그림자가 남았고, 64px 축소에서는 검이 매우 가늘어졌다. 배경 제거 성공 응답만으로 스프라이트 사용 가능 여부를 판단하지 않는다. 그림자가 남은 결과는 발 기준점 확정에 사용하지 않는다.

- 측면 가중치 1.5 적용 결과도 정면이었고 검이 누락되었다. 기존 LoRA에서 프롬프트 강조만으로 방향 문제는 해결되지 않았다.

- pixel-art-xl 비교: 윤곽과 의상 표현이 개선되었으나 여전히 정면 구도이며 검 이외의 추가 장비가 보인다. 미적 개선을 측면 생성 성공으로 간주하지 않는다.
- direction-probe는 대기 기준 후보가 아니라 측면 방향을 만들 수 있는지 확인하는 보행 자세 진단이다.


## 최종 판정

6개 조건의 실제 생성과 원본/64px 검수를 완료했다. 확정한 측면 기준 이미지는 **없다**. 기준 이미지 채택 조건을 낮추어 다음 단계로 진행하지 않는다.

| 조건 | 소요 시간(초, 대기·로딩·후처리 포함) | 판정 |
|---|---:|---|
| 512 / Redmond 0.85 | 116 | 정면에 가까움, 큰 색 블록으로 장비 구분 어려움 |
| 512 / Redmond 0.45 | 80 | 형태 개선, 정면 및 불필요한 장비 |
| 1024 / Redmond 0.45 | 144 | 선명도 개선, 정확한 측면 아님 |
| 측면 강조 / Redmond 0.45 | 196 | 정면 유지, 검 누락 |
| 측면 강조 / pixel-art-xl 0.45 | 181 | 윤곽·장비 표현 개선, 정면 유지 |
| 짧은 측면 보행 설명 / pixel-art-xl 0.45 | 180 | 약간 비스듬한 구도, 순수 측면·보행 지시 미충족 |

평가는 한 캐릭터와 한 시드에 한정한다. 다른 시드·모델·생성 방식이 불가능하다는 뜻이 아니다. 이번 비교에서는 해상도와 스타일 개선만으로 방향 문제가 해결되지 않았다.

### 후처리 개선 및 한계

- 신경망 배경 제거가 pixel-art-xl 결과의 밝은 검 일부를 제거하는 현상을 실제로 확인했다.
- `removeFlatBackground`를 실험 대안으로 추가했다. 가장자리 색상 중앙값을 추정하고 RGB 채널별 차이 12 이하인 연결 배경만 제거한다. 가장자리의 95%가 배경과 일치해야 한다.
- 원본에 남은 외곽의 색 노이즈 2픽셀을 발견했다. 경계에 닿은 독립 성분 중 원본 4픽셀 이하만 제거하며, 더 큰 경계 성분은 보존해 잘림 검사를 받게 한다.
- 단색 방식에서는 검의 세로 실루엣이 더 잘 보존됐다. 그러나 지면 그림자와 캐릭터에 둘러싸인 배경은 남을 수 있다. 사진용 범용 배경 제거로 사용하지 않는다.
- `pixelxl-flat-check` 결과도 정면·그림자 문제로 채택하지 않는다. 모든 mask-check 산출물은 진단 전용이다.
- 그림자가 남으면 발 기준점이 실제 발이 아닌 그림자의 아래쪽을 따를 수 있다. 따라서 현재 정규화 결과를 애니메이션의 확정 피벗으로 쓰지 않는다.
- 두 배경 제거 방법은 실험 스크립트에서 비교했으며 서비스의 기본 배경 제거 방식을 자동 교체하지 않았다.

```sh
node scripts/prepare-reference.mjs <candidate.png> <output-directory> flat
```

### 다음 품질 실험의 작업 범위

1. 측면 방향이 명확한 참조 이미지 또는 자세/윤곽 템플릿을 입력 조건으로 사용하는 워크플로우를 구성한다.
2. 정면 기준 이미지를 억지로 확정하지 않고, 조건 입력으로 측면 전신 1장을 먼저 만든다.
3. 지면 그림자 없는 단색 배경과 검의 최소 두께를 함께 검증한다.
4. 검수된 기준 이미지가 생긴 뒤 idle 핵심 자세 2개에서 외형 유지 여부를 확인한다.
5. 이 단계가 통과되기 전 P1 저장/작업 큐와 전체 동작 확장은 진행하지 않는다.

텍스트 전용 생성의 무조건 성공을 전제로 하지 않는다. 필요한 추가 모델의 호환성·설치 용량·실행 메모리는 다음 조건 입력 실험에서 확인해야 한다. 현재는 참조 조건 모델 설치와 5캐릭터 평가는 수행하지 않았다.

### 검증

이미지 처리 테스트 9개 통과. 단색 배경의 얇은 검 보존, 내부 배경색 보존, 작은 경계 노이즈와 큰 경계 성분의 구분을 포함한다. lint 오류 없음(기존 img 경고 2개). 실제 생성 6건 및 신경망/단색 배경 제거 실행을 검수했다. 전체 품질 게이트는 미통과다.

후속 결과: [윤곽·참조 이미지 제어 실험](control-quality.md)에서 이번 텍스트 전용 실패를 바탕으로 측면 제어를 추가했고, 한 자세의 기준 후보를 확보했다.
